# Agent adapters

One small data-and-generator object per agent in `src/agents/<id>.ts`, typed by `AgentAdapter`
(`src/agents/types.ts`):

| Field | Meaning |
|---|---|
| `id`, `displayName`, `binaries` | identity; the first binary on PATH wins |
| `skillDirs` | project folders where `lr-*` skills must appear |
| `followsSymlinks` | `true` or `"unverified"` (copy mode) |
| `invoke(skill)` | how the user calls a skill (`$lr-init`, `/skill:lr-init`, `/lr-init`) |
| `extraFiles(skills)` | extra generated files (OpenCode command shims) |
| `direct` | `subagentFile(role, model, readOnly)`, `resumable`, `spawnHint`; absent = no Direct |
| `delegate` | `skill`, `sessionField`, `resumeFlag`, `resumable`, `readOnly` (`enforced`/`best-effort`/`none`), `effortFlag` (`--effort`/`--variant`/null), `cleanEnv`, `modelFormat`, `writeFlags` (write runs only; agy `--dangerously-skip-permissions`), `printTimeoutFlag` (agy `--print-timeout`, set to the run timeout), `authFromModels` (doctor treats a reported model list as logged in; agy); absent = no relay |
| `quotalensProvider` | QuotaLens provider id |
| `envMarkers` | environment variables hinting the Lead runs in this host |
| `postInstallNotes` | printed by `looprch add`, some surfaced by doctor |
| `generatedGlobs` | gitignore patterns for generated files |
| `verified` | spike status per capability |
| `experimental` | shown as a doctor warning |

Generated subagent files contain only frontmatter (name, model, read-only flag) and one line:
"Follow the brief you are given exactly; return the result block it asks for." All role knowledge
is in the brief, so core updates apply without regenerating them. Every generated file carries
`generated by looprch: do not edit`.

## Adding an agent

1. `src/agents/<id>.ts` with the adapter object.
2. Add the id to `AGENT_IDS` (`src/core/config.ts`) and the registry in `src/agents/index.ts`.
3. A snapshot case in `test/unit/agents.test.ts`, and a fake binary in `test/helpers/fakes.ts` if it
   has a relay.
4. `docs/user/agents/<id>.md` and a link in `docs/user/index.md`.
5. Run the verification spikes for it and record them in `spike-results.md`.

The capability values become config validation rules through `agentCaps()`.

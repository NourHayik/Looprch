# Attach a project

```sh
looprch add [path]                          # interactive multi-select (↑/↓, Space, Enter)
looprch add . --agents codex,cursor --yes   # scripts
looprch add . --copy                        # copy skills instead of symlinking them
looprch remove <agent>
looprch list
```

`add` resolves the git root (or the given path), refuses a Looprch 5.x `.looprch/` folder, shows
the agents already enabled and offers the remaining ones. Running it again with no new selection
repairs links and files and changes nothing else.

## Files written

| Path | What | Git |
|---|---|---|
| `.agents/skills/lr-*` (10 skills) | symlinks to `~/.looprch/current/assets/skills/` or copies with `.looprch-version` | ignored |
| `AGENTS.md` block between `<!-- looprch:begin -->` and `<!-- looprch:end -->` | short static rules for agents | committed |
| `.looprch/config.json` | your project configuration | committed |
| `.gitignore` block between `# looprch:begin` and `# looprch:end` | runtime folders, skill links, generated files | committed |
| `.cursor/agents/lr-<role>.md`, `.codex/agents/lr-<role>.toml`, `.opencode/agents/lr-<role>.md` | Direct subagent definitions (model only), generated when a role is Direct | ignored |
| `.opencode/commands/lr-*.md` | OpenCode command shims | ignored |

Looprch never overwrites a file it did not create; it reports it instead. Generated files carry
the marker `generated by looprch: do not edit`. Set `integrations.commit_generated` to `true`
(`looprch config set integrations.commit_generated true`) to commit them.

## Symlink or copy

Skills are symlinked when every enabled agent that reads that folder is known to follow
symlinks (Codex, OpenCode). Otherwise, and on WSL, Looprch copies the skill folders and stamps
them with the core version; `looprch update` refreshes copies. See
[docs/dev/symlink-and-copy-strategy.md](../dev/symlink-and-copy-strategy.md).

## Fresh clones

Skill links contain absolute paths, so they are gitignored. After cloning a Looprch project run
`looprch add .` once.

## Removing an agent

`looprch remove <agent>` deletes that agent's Looprch-owned files. It fails while a role or
fallback still uses the agent and lists those roles.

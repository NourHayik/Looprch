# 03 — Project attachment and agent integrations

## 1. `looprch add [path]`

Interactive (default) or `--agents codex,cursor --yes` for scripts.

1. Resolve the project root (git root if inside a repo, else the given path).
2. Refuse if a Looprch 5.x layout is present (`.looprch/VERSION` 5.x or `.looprch/control/`).
3. If `.looprch/config.json` exists, this is an existing project: print `Enabled: Codex, Cursor`
   and offer a multi-select (`@clack/prompts`, ↑/↓, Space, Enter) of the remaining supported
   agents only. Otherwise offer all agents.
4. For each newly selected agent: run its adapter (files below), record it in `config.json`.
5. Write or refresh the shared layer (skills links, `AGENTS.md` block, `.gitignore` entries).
6. Register the project in `~/.looprch/projects.json`.
7. Print a summary: files created, per-agent next step (e.g. `hermes skills trust`), and
   "Run /lr-init inside your agent" with the agent-specific invocation syntax.

Idempotency rules: never duplicate a link, file or block; regenerate Looprch-owned files only;
never overwrite a file Looprch did not create (report it instead); re-running with no new
selection repairs links and exits successfully.

`looprch remove <agent>` removes that agent's Looprch-owned files and fails if a configured role
still uses the agent (lists the roles to reassign first).

## 2. Files written in the project

Shared (once, for any selection):

| Path | Kind | Git |
|---|---|---|
| `.agents/skills/lr-<cmd>` (10 skills) | symlink → `~/.looprch/current/assets/skills/lr-<cmd>` (copy mode: copied folder + `.looprch-version`) | ignored |
| `AGENTS.md` block between `<!-- looprch:begin -->` / `<!-- looprch:end -->` | short static text: project uses Looprch, run `/lr-status`, never tick `phases/todo.md`, never commit as an agent | committed |
| `.looprch/config.json` | project config | committed |
| `.gitignore` block | `.looprch/runs/ .looprch/packets/ .looprch/test-evidence/ .looprch/reports/ .looprch/lock .looprch/backups/ .sev3-cache/` + Looprch skill links | committed |

Per agent (only for selected agents): see the adapter table. Generated subagent files contain only
frontmatter (name, model, read-only flag where supported) and one line: "Follow the brief you are
given exactly; return the result block it asks for." All role knowledge lives in the brief, so core
updates apply without regenerating them. They are regenerated by `add`, `update` and
`/lr-init` when models change. Generated files are gitignored by default (they may contain
machine-specific model availability); a config flag can commit them.

## 3. Agent adapter object

```ts
interface AgentAdapter {
  id: "codex" | "cursor" | "agy" | "kimi" | "hermes" | "opencode" | "grok";
  displayName: string;
  binaries: string[];                 // first found wins, e.g. ["cursor-agent", "agent"]
  skillDirs: string[];                // where lr-* skills must appear
  invoke(skill: string): string;      // "/lr-init", "$lr-init", "/skill:lr-init"
  extraFiles?(ctx): GeneratedFile[];  // command shims, rules
  direct?: { subagentFile(role, model, readOnly): GeneratedFile; resumable: boolean };
  delegate?: { skill: string; sessionField: string; resumeFlag: "--session" | "--conversation" | null;
               readOnly: "enforced" | "best-effort" | "none"; effortFlag: "--effort" | "--variant" | null;
               cleanEnv: boolean };
  quotalensProvider?: string;
  postInstallNotes?: string[];
}
```

Adding an agent = one adapter file + registry line + fixture test + docs page.

## 5. Why symlinks only for skills

- Absolute links break for collaborators, CI, cloud agents and containers → gitignored; a fresh
  clone runs `looprch add .` (documented).
- Only static core content is linked; nothing project-specific is ever written through a link, so
  a project cannot modify the shared core or another project.
- Copy mode is the fallback per agent (if a spike shows it does not follow links) and is refreshed
  by `looprch update` through `projects.json`.
- A single directory link (`.agents/skills/looprch -> …/skills`) is NOT used because skill
  discovery expects `skills/<name>/SKILL.md` one level deep.
